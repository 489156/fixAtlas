# 발행·GEO·SNS 자동화 설계 (2026-11-18)

근거: `docs/research/R9`(플랫폼 정책·도구), `R12`(GEO·SNS API 검증), 이번에 원문으로 다시 확인한 두 가지(네이버 약관·운영정책, X 요금표).
표기: **[검증]** 원문 직접 확인 · **[조사]** 조사 보고 · **[estimate]** 추정 · **[unverified]** 미확인 · **[판단]** 작성자 판단

## 0. 결론

1. **자동발행이 되는 채널과 안 되는 채널이 정책으로 갈린다.** 네이버 블로그는 글쓰기 API가 없다. 약관·운영정책은 "사전 허락 없이 자동화된 수단(매크로·봇 등)으로 게재한 게시물"을 제한한다 [검증 2026-11-18]. 그래서 네이버는 **사람이 에디터에서 예약발행**한다. 자체 사이트와 SNS(공식 API·Buffer)만 자동화한다.
2. **GEO(AI 답변 인용)의 원본은 자체 사이트다.** 네이버 블로그 robots.txt는 GPTBot·OAI-SearchBot·PerplexityBot·ClaudeBot·Claude-SearchBot 등을 막는다 [검증]. 사이트의 robots.txt는 지금 모든 봇을 허용한다(`scripts/generate-sitemap.mjs`). 남은 병목은 **SPA 본문이 HTML에 없다는 점**이다. 사전 렌더링이 GEO 1순위 작업이다.
3. **별도 블로그 플랫폼(WordPress·Ghost)은 들이지 않는다** [판단]. 인용될 숫자(공식가·표본·방법론)가 이미 사이트 DB와 페이지에 있다. 같은 도메인에서 사전 렌더링하는 편이 데이터와 인용 지면을 하나로 묶는다. API 예약발행이 되는 블로그는 WordPress·Ghost·Blogger뿐이고 [조사 R9], 티스토리 API는 2024-02에, Medium API는 지원이 종료됐다.
4. **SNS는 새로 만들지 않고 블로그 글의 원문 캡처와 카드를 재사용해 배포한다.** 템플릿 카드만 올리면 저노력 콘텐츠로 읽히므로(R13 G4) 캡처나 직접 찍은 사진을 함께 쓴다. 5주차부터 Threads·Instagram을 Buffer 무료 플랜으로 시험한다. X는 비용이 작지만(URL 게시 $0.200/건 [검증]) 우선순위가 낮다. Reddit 자동화는 금지 수준으로 본다. YouTube·TikTok은 영상 제작이 필요해 보류한다.
5. **같은 본문을 두 곳에 올리지 않는다.** 네이버 글은 날짜가 박힌 리포트로, 사이트는 갱신되는 데이터 페이지(제품·방법론·리포트 요약)로 나눈다. 중복 문서로 묶여 한쪽만 노출되는 위험을 피하기 위해서다(네이버 유사문서 처리 세부 기준은 [unverified]).

## 2. GEO: 자체 사이트를 인용 원본으로 만든다

**하는 것** (우선순위 순)

1. **사전 렌더링 (P1)**: 빌드 뒤 공개 경로(`/`, `/methodology`, `/products/:cat/:slug`, 리포트 페이지)를 헤드리스 브라우저로 렌더링해 `dist/<경로>/index.html`로 저장한다. 이미 쓰는 Playwright로 의존성 추가 없이 구현할 수 있다 [판단]. 호스팅이 정적 파일을 SPA 폴백보다 먼저 내보내는지 배포처 문서로 확인해야 한다 [unverified]. 제보가 늘면 통계가 바뀌므로 매일 1회 다시 빌드한다.
   근거: 구글은 SPA의 서버 렌더링·사전 렌더링을 권하고, AI 크롤러가 JS를 실행한다는 보장은 없다 [조사 R12 G3]. 네이버 서치어드바이저도 SPA에 SSR을 권한다 [조사 R9 S6].
2. **리포트 요약 페이지 (P2)**: `/reports/<slug>`. 네이버 글과 같은 사실을 쓰되 **데이터 중심 구조**로 만든다. 요약 박스(중앙값·범위·표본·확인일), 출처 목록, 방법론 버전, 제품 링크로 구성하고 네이버 본문을 복사하지 않는다. 질문형 제목과 첫 문단이 인용에 가장 관련 있던 요인이다 [조사 R12 G5].
3. **색인 신호 (P3)**: 배포할 때 바뀐 URL을 IndexNow로 알리고(네이버·Bing), 사이트맵 `lastmod`를 갱신한다. Search Console과 서치어드바이저에 사이트를 등록한다. 구글 AI 기능은 색인·스니펫 허용·Search Console 설정(기본 포함)만 갖추면 된다 [조사 R12 G1].
4. **측정 (구현 완료)**: UTM이 없는 방문은 referrer 호스트로 출처를 기록한다(`src/lib/referrer.ts`). ChatGPT·Perplexity·Claude·Gemini·Copilot 유입은 `ai:*`로 묶여 관리자 KPI 패널의 "블로그·캠페인 유입" 표에 나온다. 호스트만 저장하고 경로·검색어는 저장하지 않는다.

**하지 않는 것**: llms.txt·AI 전용 마크업(구글은 쓰지 않음 [R12 G2]), 질문 변형마다 페이지 대량 생성(구글 경고 [R12 G2]), 키워드 반복(효과 없거나 손해 [R12 G4]).

**한계**: GEO 학술 근거는 영어·미국 기준이다. 네이버 AI 브리핑은 출처 선정 기준이 공개되지 않았다 [조사 R9]. 네이버 AI 브리핑에는 네이버 블로그가 주로 인용된다는 업체 조사(출처의 46.5%)가 있다 [조사 R10]. 그래서 네이버 블로그는 네이버 AI 브리핑용 지면으로도 유지한다.

## 3. 발행 파이프라인

```
원고 docs/blog/naver/*.md (claims 출처 기록 포함)
  │  check-claims  ── 숫자 출처·확인일·금지표현·어미 혼용
  │  [사람] 24시간 뒤 원문 재확인
  ├─▶ 네이버 블로그 : naver-export(도메인·UTM·카드 숫자 대조) → [사람] 붙여넣기 → 예약발행
  ├─▶ 자체 사이트   : 리포트 데이터 → 빌드·사전 렌더링 → 배포 → 사이트맵·IndexNow
  └─▶ SNS (네이버 발행 다음 날)
        원문 캡처·직접 사진 + 카드 PNG(사이트에 공개 URL로 호스팅) + 채널별 캡션 + 채널별 UTM(utm_source=threads|instagram|x)
        A안 Buffer (지금)  : 무료 플랜 3채널, 채널당 예약 10건. 사람이 캡션·이미지를 올리고 예약
        B안 자체 큐 (나중) : Supabase 테이블 social_queue + 15분 주기 Edge Function → 공식 API
```

**B안으로 넘어가는 조건** [판단]: 예약 대기 글이 채널당 10건을 넘거나, 월간 데이터 리포트(T4)를 사이트가 자동 생성하기 시작할 때.

B안 설계 요점:
- 테이블 `social_queue(channel, scheduled_at, caption, image_urls, status, external_id, error, attempts)`. 상태는 `queued → publishing → done | failed`로 바뀌고, 실패는 3회까지 재시도한다.
- 게시 전에 한도를 확인한다. Instagram은 `content_publishing_limit`로 확인하고, Threads는 24시간 게시 수를 직접 센다.
- 토큰은 Supabase secrets에 두고 만료 전에 갱신한다(Meta 장기 토큰 유효기간 [unverified]).
- 캡션 숫자는 이미 대조를 마친 원고·카드의 숫자만 쓴다. 새 숫자를 넣으려면 원고 출처 기록에 먼저 추가한다.
- 캡션에도 AI 사용을 숨기지 않는다. 블로그 글의 "만든 방법" 줄을 짧게 줄여 넣거나 글 링크로 대신한다(R13 S3: 숨겼다 들키는 경우가 가장 나쁨).

**채널별 캡션 형식** (예: 2편)

| 채널 | 형식 | 예 |
|---|---|---|
| Threads | 3줄 요약 + 출처·확인일 + 링크 1개, 원문 캡처 1장 | "LG전자 출장비: 평일 28,000원 / 평일 18시 이후·주말 33,000원 / 여름 성수기 야간·휴일 38,000원. LG 요금/보증 안내 2026-11-18 확인(캡처). 견적서 세 칸 읽는 법은 글에: 링크" |
| Instagram | 캐러셀: 원문 캡처 1~2장 + 직접 사진 + 요약 카드 1장, 캡션 첫 줄에 결론, "링크는 프로필에서" | 캡션 링크는 눌리지 않는다는 것이 일반적 관행이다 [unverified] |
| X | 결론 1문장 + 링크 | URL 포함 게시 $0.200/건. 계정에 Automated 라벨 |

## 4. 단계별 도입 (`docs/BLOG_PLAN.md` 3장과 같은 내용)

| 시점 | 채널 | 방식 | 넘어가는 조건 |
|---|---|---|---|
| 1~4주 | 네이버 블로그 + 자체 사이트 | 사람이 예약발행, 사이트 사전 렌더링 개발 | — |
| 5주~ | + Threads, Instagram | Buffer 무료, 원문 캡처·사진·카드 재사용, 주 2~3회 | 블로그 주 2편을 4주 연속 유지 |
| 3개월~ | + X (선택) | Buffer | SNS 유입 세션이 블로그 유입의 10% 이상 [판단] |
| 6개월 후 재검토 | YouTube Shorts, TikTok | 영상 제작 필요, TikTok 감사 | 2단계(커뮤니티) 진입 시 |
| 하지 않음 | 네이버 자동화, Reddit 자동화 | 정책 위반 | — |

## 5. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 네이버 자동화 적발 | 유일한 유통 채널 상실(치명) | 자동화 도구 금지. 붙여넣기용 원고만 만든다 |
| 네이버·사이트 중복 문서 | 한쪽만 노출 | 사이트는 데이터 페이지, 블로그는 날짜 리포트로 본문을 다르게 쓴다 |
| SNS 반복 게시 스팸 판정 | 계정 제한 | 같은 캡션 재게시 금지, 채널당 하루 1건 이하 |
| AI 유입 측정 누락 | GEO 성과 판단 불가 | referrer 출처 기록(구현). 앱 내 브라우저 등 referrer가 비는 경우는 잡히지 않음 |
| 사전 렌더링 숫자가 낡음 | 오래된 날짜가 인용됨 | 매일 다시 빌드하고, 페이지에 확인일을 표시 |

## 6. 확인 못 한 것

- 스마트에디터 붙여넣기 서식 유지, 예약발행 가능 범위: 첫 글 발행 때 확인한다(`docs/blog/naver/README.md`).
- Buffer의 Threads·Instagram 게시 형식 제약(캐러셀 장수 등): Buffer 계정에서 확인한다.
- 호스팅의 사전 렌더링 파일 우선 제공 여부: 배포처가 정해지면 확인한다.
- 네이버 유사문서 판정 기준: 서치어드바이저 가이드 원문으로 확인한다.
