# 편집 기준서 — 신뢰성 검증 · 윤문 · 배치 · 디자인

모든 글은 이 기준을 통과해야 발행한다. 자동 점검은 `node scripts/check-claims.mjs <원고.md>`.

## 1. 신뢰성 검증 (5단계)

| 단계 | 할 일 | 산출물 | 자동화 |
|---|---|---|---|
| ① 주장 뽑기 | 원고의 모든 숫자·정책·기간·비율을 한 줄씩 적는다 | 원고 앞머리 `claims:` 출처 기록 | `check-claims`가 출처 기록에 없는 숫자를 찾아낸다 |
| ② 출처 등급 매기기 | 아래 등급표에서 가장 높은 등급의 출처를 찾는다 | 출처 기록의 URL | https 아닌 출처는 실패 |
| ③ 원문 재확인 | 출처 페이지를 **그날 직접 열어** 숫자를 본다. 정상가/회원가/할인가, VAT, 적용 모델·기간을 구분한다 | 출처 기록의 확인일 | 확인일 90일 경과 시 실패(`--max-age`) |
| ④ 표본 규칙 | 사용자 제보 수치는 표본 수와 함께. n<3 범위 미표시, n<5 중앙값 미표시 | 본문 표기 | 사이트 통계 모듈이 같은 규칙 적용 |
| ⑤ 하루 묵혀 재검 | 1인 운영이면 작성 다음 날 처음부터 다시 읽고 ③을 한 번 더 | 점검표 체크 | — |

**출처 등급**

| 등급 | 예 | 쓰는 법 |
|---|---|---|
| A 1차·공식 | 제조사 공식몰·서비스 요금 안내, 정부·소비자원 보도자료, 법령 | 그대로 인용 (확인일 필수) |
| B 공신력 2차 | 언론 보도(원 보도자료를 인용한 것), 학술 논문 | "보도 기준"으로 표기, 가능하면 A로 대체 |
| C 커뮤니티·블로그 | 카페·블로그 사례 | **수치 근거로 쓰지 않는다.** 링크·요약만, "개별 사례"로 표기 |
| D 생성형 AI 답변·근거 없는 요약 | AI 브리핑 수치, 출처 없는 표 | 사용 금지 |

**발행 후**: 분기마다 출처 기록 전체를 다시 열어 본다. 숫자가 바뀌면 표·한 줄 결론·업데이트 이력을 함께 고친다. 공식 요금 개정 예고(예: 삼성 에어컨 2027-01-01)는 캘린더에 재확인 일정을 넣는다.

## 2. 윤문 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 첫 문장 | **질문에 대한 답 + 숫자 + 기준일**. 서론·인사말로 시작하지 않는다 | "LG전자 출장비는 평일 28,000원입니다(2026년 11월 공식 안내 기준)." |
| 제목 | 사람들이 실제로 묻는 문장에 맞춘다. 브랜드·모델·항목 + "얼마/비용" + 연·월 | "LG전자 출장비 얼마? 2026년 시간·계절별 정리" |
| 문장 | 한 문장 50자 안팎, 한 문단 2~3문장. 어미는 **블록 단위로 통일**한다(§5): 결론·표·고지는 합니다체, 설명·FAQ·확인 기록·CTA는 해요체. 한 문단 안에서는 섞지 않는다 | "LG전자 출장점검료는 평일 28,000원입니다." / "급하지 않다면 평일 18시 이전으로 예약하세요." |
| 숫자 | 천 단위 쉼표, 단위 붙여 쓰기(28,000원), 범위는 "~", 날짜는 2026-11-17 또는 2026년 11월 17일로 통일 | — |
| 단정과 추측 | 출처가 있으면 단정, 없으면 "확인하지 못했습니다" 또는 "표본이 부족합니다". "~것 같습니다" 금지 | — |
| 과장 | "최저가 보장·무조건·100%·업계 최저" 금지(표시광고 위험) | — |
| 업체 | 수리점·설치기사 **실명 평가 금지**. 제조사 공식 요금은 출처로 인용 가능 | — |
| 안전 등급 | 한글을 먼저 쓰고 영문 병기: "직접 점검 가능(Safe Check)", "주의(Caution)", "전문가만(Expert Only)", "직접 수리 금지(Do Not DIY)" | — |
| 질문형 소제목 | 독자가 검색할 질문을 소제목으로 쓴다(예: "출장비는 수리를 안 해도 내나요?") — 같은 사이트 안 인용과 가장 관련 있던 요인이 "질문과 맞는 제목·문단"이었다 [R12 G5] | — |

## 3. GEO·검색을 위한 원칙 (근거: `docs/research/R12`)

1. **AI 전용 장치보다 검색 기본기.** 구글은 AI 기능 최적화를 "여전히 SEO"로 본다(llms.txt·AI 전용 마크업 불필요). 색인, 스니펫 허용, 질문형 제목·첫 문단이 우선.
2. **가격·기준일·표본 수·출처를 본문 텍스트로.** 이미지 속 표는 검색·AI가 읽지 못할 수 있다. 표는 텍스트 표로.
3. **오래된 날짜를 방치하지 않는다.** 업데이트 이력과 확인일을 갱신한다.
4. **키워드 반복 금지.** 생성형 엔진에서 효과가 없거나 손해였다.
5. **채널 역할 분리**: 네이버 블로그는 AI 검색 크롤러(GPTBot·OAI-SearchBot·PerplexityBot·ClaudeBot 등)를 robots.txt로 차단한다(2026-11-18 확인). ChatGPT·Perplexity 인용은 **자체 사이트**가 맡는다 → 사이트 본문은 사전 렌더링 필요.
6. **같은 내용을 질문 변형마다 페이지로 복제하지 않는다**(구글 경고). 한 주제 한 페이지, 갱신으로 키운다.

- **이미지**: 카드 3장(요약·체크리스트·제보 모집) + 직접 촬영 사진 0~2장 = 3~5장. R10에서 수리·비용 글은 3~6장이었다. 표는 이미지로 넣지 않고 에디터 표로 넣는다(검색·AI가 읽는 텍스트로 남긴다).
- **링크**: 출처 링크는 제한하지 않는다(차별점). 행동 유도 링크는 2개까지(R11: 같은 CTA 반복은 역효과 사례).
- **댓글 요청**: "댓글로 모델명과 받은 견적을 남겨 주세요." 댓글 금액은 C등급이라 통계에 넣지 않고, 다음 글의 질문 목록으로만 쓴다.
- **첫 글 3편은 모바일 미리보기로 표·인용구 모양을 확인한다.** 스마트에디터 붙여넣기 서식 유지는 확인하지 못했다(도구로 네이버 접근 불가).

## 5. 문체 — 어미를 블록 단위로 나눈다

R10에서 반응 지표가 보인 3곳은 모두 해요체를 섞었다. 합니다체만 쓰면 딱딱하고, 해요체만 쓰면 숫자의 무게가 가볍다. 그래서 블록 단위로 정한다.

| 합니다체 | 해요체 |
|---|---|
| 공개 줄, 한 줄 결론, 표·표 설명, 데이터 요약, 고정 고지 | 설명 문단, 안전 박스의 행동 지시, 체크리스트, 편집자 확인 기록, FAQ 답, CTA |

금지: 반말, 감탄사·이모지 남발(⚠·📷 같은 기능 기호만 허용), "여러분 안녕하세요" 같은 인사 서론, 같은 문단 안 어미 혼용.

## 6. 디자인

**카드 이미지** (`scripts/render-cards.mjs`, 데이터: `docs/blog/cards/cards.json`)
- 1080×1080 PNG, Noto Sans KR. 위쪽에 브랜드와 "광고·제휴 없음" 칩, 아래쪽에 출처와 확인일을 **반드시** 넣는다.
- 종류는 요약(행 4개 이하), 체크리스트(항목 3~4개, 넘치면 촘촘한 배치), 제보 모집 세 가지다.
- 카드 숫자는 원고 출처 기록과 같아야 한다. `naver-export`가 카드의 숫자를 원고 `claims:`와 대조해서, 다르면 내보내지 않는다(R11의 "요약·표 숫자 불일치" 방지).
- 안전 표시는 ⚠ 기호 + 텍스트 라벨로 한다. 색만으로 구분하지 않는다(WCAG 1.4.1).

**자체 사이트** (R11 §3-2. 다음 사이트 개편 때 적용)
- 본문 16px 이상, 줄간격 1.5 이상, 한 줄 한글 40자 이하(최대 폭 약 40em), 대비 4.5:1 이상, 12px 미만 글자 금지, 양쪽 정렬 금지.
- 표: 설명형은 2열, 숫자형은 4열까지. 첫 열 고정, 머리행 고정.
- 요약 박스: 중앙값 / 중간 50% 구간 / 표본 n / 공임·부품 분리 / "포함 안 됨"(출장비·VAT) / 확인일 / 방법론 버전.
- 반응 신호: "댓글 0" 같은 빈 지표는 노출하지 않는다. 표본 n과 확인일을 신뢰 신호로 쓴다.
- Mobbin 상세 패턴 페이지는 403이라 보지 못했다. NN/g·WCAG·USWDS 기준으로 대체했다.

## 7. 바이라인과 검수 — 1인 운영을 숨기지 않는다

- 작성자와 검수자를 나눈 척하지 않는다. 바이라인은 "작성·확인 고장도감 편집자"로 쓴다. 신뢰는 방법론 링크·확인일·출처 목록·업데이트 이력으로 보완한다.
- 1인 운영 보완책: 작성 다음 날(24시간 뒤) 원문을 다시 열어 숫자를 대조하고 발행한다(§1 ⑤). 예약발행은 이 재검을 마친 뒤에 건다.
- 외부 검수자(수리 기사 등)를 확보하면 "검수: 이름(자격)"을 추가한다. 실재하지 않는 인물, AI 가상 인물은 바이라인에 쓰지 않는다.
- AI 도구는 초안·교정에 쓸 수 있다. 다만 모든 숫자는 사람이 원문을 열어 확인한다. AI 답변을 출처로 쓰지 않는다(D등급).

## 8. 자동 점검 (발행 전 필수)

```bash
node scripts/check-claims.mjs docs/blog/naver/*.md
```
```bash
SITE_URL=https://실제도메인 node scripts/naver-export.mjs docs/blog/naver/*.md
```

| 점검 | 실패 조건 | 도구 |
|---|---|---|
| 숫자 출처 | 출처 기록에 없는 숫자, https·`site:/`가 아닌 출처, 확인일 없음·90일 경과·미래 | check-claims |
| 금지 표현 | 과장(최저가 보장 등), 추측("~것 같습니다"), TODO·"링크 삽입 예정" | check-claims |

| 카드 숫자 | 카드 이미지의 숫자가 원고 출처 기록에 없음 | naver-export |
| 배치 경고 | 제보 CTA 3개 이상, 이미지 3장 미만·6장 초과, 태그 10개 초과, 제목 45자 초과, 표 4열 이상 | naver-export |
