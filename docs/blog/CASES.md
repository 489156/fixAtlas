# 사례 인용 기준 — 직접 확인 없이 실제 사례를 싣는 방법 (2026-11-19)

**배경 (운영자 지시, 2026-11-18)**: 발행할 때마다 편집자가 직접 문의하거나 사례를 구해 올 수는 없다.
독자가 믿는 근거는 "실제로 이런 일이 있었고 이렇게 풀렸다"는 사례다(R13: 직접 겪은 문제 해결 과정이 신뢰 신호).
그래서 글마다 **검증 가능한 사례 1건 이상**을 요구하고 사례의 출처를 넓힌다.
편집자의 직접 확인은 있으면 더 좋은 근거이지 필수 조건이 아니다.

## 1. 사례 출처 (신뢰도 순)

| 순위 | 출처 | 예 | 장점 | 주의 |
|---|---|---|---|---|
| 1 | 공적 사례 | 한국소비자원 품목별 피해구제사례·분쟁조정결정사례·사례집, 공정위 의결, 법원 판결 | 기관의 판단까지 적혀 있음 | 같은 품목 사례가 없으면 같은 기준이 적용된 다른 품목을 쓰고 "같은 기준"이라고 밝힌다 |
| 2 | 언론 보도 속 소비자 사례 | 디지털데일리 2025-07-17 샤오미 로봇청소기 A/S 사례 | 최근 사례, 품목을 맞추기 쉬움 | 매체·날짜를 문장에 쓰고, 인용은 1~2문장, 나머지는 요약 |
| 3 | 자사 제보 | 고장도감 수리비 제보와 후기 | 우리만 가진 1차 자료, 시간이 갈수록 늘어남 | 동의 범위 확인 필요(§5), 식별 정보 제거, 출처는 `site:/` |
| 4 | 제조사 공식 회신·안내 | LG전자 고객센터 회신(2026-11-18) | 정책의 현재 상태를 확인 | 회신 날짜를 쓰고 출처는 `직접:`. 공식 페이지와 대조해 일치하는 부분은 웹 출처를 함께 단다 |
| 5 | 공개 커뮤니티·리뷰 | 제조사 공식 커뮤니티, 공식몰 리뷰 | 양이 많음 | 닉네임·사진 등 식별 정보를 쓰지 않고 요약 위주. 이용약관과 robots.txt를 지킨다 |

## 2. 쓰는 규칙

1. 남의 사례를 우리 경험처럼 쓰지 않는다. 문장 안에 누가(기관·매체), 언제를 밝힌다.
2. 원문은 1~2문장만 큰따옴표로 인용하고 나머지는 요약한다. 출처를 밝힌다(저작권법 제28조 공표된 저작물의 인용, 제37조 출처의 명시).
3. 이름·닉네임·사진·연락처처럼 개인을 알아볼 수 있는 정보는 쓰지 않는다.
4. 다른 품목의 사례는 기준을 보여 주는 근거로만 쓰고 "같은 기준이 적용된 사례"라고 밝힌다. 한 글 한 품목 원칙은 그대로다.
5. 출처 기록에 비고가 `사례:`로 시작하는 줄을 넣고 원문 인용 문구 칸을 채운다. `verify-sources`가 그 문구가 원문에 있는지 대조한다. 인용 문구가 없으면 사례로 인정하지 않는다(`check-claims`의 `no_case`).
6. 24개월이 지난 사례는 본문에 게시일을 쓰고, 그 기준이 지금도 같은지 현행 고시·공식 안내와 대조한다.

예:
```
  - 2023년 2월 / 2회 | https://www.kca.go.kr/odr/cm/cm/boardsDtl.do?seq=1003406164&brdId=00000006 | 2026-11-19 | 사례: 한국소비자원 피해구제 사례(안마의자, 같은 가전제품 기준) | 동일하자에 대해 2회까지 수리하였으나 하자가 재발한 경우
```

## 3. 찾는 방법 ([AI] 작업)

- 질의 틀: "<품목> <쟁점> 피해구제 사례", "<품목> 분쟁조정 결정", "<품목> 수리 거부 소비자 기사". 같은 품목이 없으면 기준의 핵심어로 찾는다(예: "동일하자 2회 수리 재발 환급 사례").
- 한국소비자원 사례 게시판(`kca.go.kr/odr`)은 robots.txt가 사이트 전체의 자동 접근을 막는다(`Disallow: /`). 게시판을 자동으로 훑는 도구는 만들지 않는다. 검색엔진으로 찾고, 인용할 사례 페이지만 연다.
- 소비자원 보도자료는 정책브리핑(`korea.kr`, robots.txt 허용)에도 실리는 경우가 많다. 같은 자료가 있으면 그쪽 주소를 출처로 쓴다.
- 찾은 사례는 원고 출처 기록에 `사례:` 줄로 넣고 `npm run blog:verify`로 대조한다.

## 5. 결정이 필요한 것 [판단]

1. **소비자원 페이지 대조 방식**: 소비자원 robots.txt는 전체를 막는다. `verify-sources`는 인용한 페이지만, 발행 전날 한 번씩 연다(게시판 순회·대량 질의 없음). 이 방식을 계속 쓸지 정해야 한다.
   - 허용하지 않으면 정책브리핑 사본이 있는 자료만 자동 대조하고, 나머지는 게시일 기준 인용으로만 쓴다.
2. **자사 제보를 블로그에 인용할 수 있는지**: 지금 제보 양식의 동의 문구는 "제보 내용은 작성자를 알 수 없는 형태로 다른 이용자에게 집계·표시됩니다"이다. 외부 블로그·SNS에 개별 후기를 인용하는 것까지 포함하는지 불분명하다.
   - 제안 문구: "제보 내용(후기 문장 포함)은 작성자를 알 수 없는 형태로 고장도감 블로그·SNS에 사례로 인용될 수 있습니다."
   - 바꿀지는 개인정보 처리 방침과 함께 정한다. 정해지면 [AI]가 양식·방침 문구를 고친다.
