# 네이버 블로그 발행본 — 1주차 3편과 발행 절차

네이버 블로그에는 글쓰기 API가 없고, 이용약관(2026-10-01 시행)과 게시물 운영정책(2026-07-07 시행)이 **"네이버의 사전 허락 없이 자동화된 수단(예: 매크로 프로그램, 로봇(봇), 스파이더, 스크래퍼 등)을 이용하여 게재한 게시물"**을 제한한다(2026-11-18 원문 확인: policy.naver.com/policy/service.html, service_group.html). 그래서 이 폴더의 스크립트는 **붙여넣을 원고만 만든다.** 발행은 사람이 스마트에디터에서 하고, 예약발행 기능을 쓴다. 매크로·RPA·브라우저 자동화로 올리지 않는다.

## 글마다 하는 일 (약 40분, 직접 확인 포함 [판단])

1. **직접 확인 칸 채우기**: 원고의 `[[직접 확인: …]]`를 실제로 한 일로 바꾼다. 고객센터 문의라면 날짜, 질문, 답 요지를 적고, 사진이라면 개인정보를 가린 사진을 넣는다. front matter의 `firsthand:`에 날짜와 무엇을 했는지 적는다(예: `firsthand: 2026-11-23 LG전자 고객센터 전화 문의(질문 2개)`). 답에 금액이 있으면 출처 기록에 `직접:LG전자 고객센터 전화 2026-11-23` 형식의 줄을 추가한다. "쓴 사람" 바이라인은 한 번 정하면 모든 글에 같은 문장을 쓴다.
2. **원문 재대조와 캡처 (전날)**
   ```bash
   NODE_PATH=$(npm root -g) node scripts/verify-sources.mjs docs/blog/naver/01-battery-price.md --evidence=docs/blog/evidence
   ```
   "불일치"가 나오면 원문을 열어 숫자·문구를 고친다. 본문, 출처 기록, (쓴다면) SNS 카드, 수정 이력을 함께 고친다. "이미지(캡처로 눈 확인)" 행은 캡처를 직접 보고 숫자를 확인한다. 캡처가 실패하거나 어둡게 나오면 한 번 더 실행한다. 확인이 끝나면 "만든 방법" 줄의 날짜 칸에 오늘 날짜를 적는다.
3. **점검** (여러 글을 함께 넣어야 글 사이 중복도 잡힌다)
   ```bash
   node scripts/check-claims.mjs docs/blog/naver/0*.md
   ```
4. **붙여넣기용 페이지 만들기**: 도메인이 확정돼야 한다.
   ```bash
   SITE_URL=https://실제도메인 node scripts/naver-export.mjs docs/blog/naver/01-battery-price.md
   ```
   `naver-out/<slug>.html`을 브라우저로 열면 제목·태그·본문·원문 캡처 PNG와 에디터 입력 순서가 나온다.
5. **스마트에디터**: 제목 → 본문 붙여넣기 → 인용구·표 모양 정리 → 캡처·사진 업로드(첫 장을 대표 이미지로) → 태그 → **모바일 미리보기** → 예약발행.
6. **발행 후**: 링크를 눌러 사이트가 열리는지, 관리자 KPI 패널의 "블로그·캠페인 유입"에 해당 캠페인이 잡히는지 본다. 댓글로 오류 지적이 오면 2번부터 다시 하고 수정 이력에 남긴다.

## 아직 확인하지 못한 것 (첫 글에서 확인)

- 붙여넣을 때 표·인용구·굵게가 유지되는지. 도구로 네이버에 접근할 수 없어 확인하지 못했다. 깨지면 에디터의 표·인용구 기능으로 다시 만든다.
- 예약발행을 며칠 뒤까지, 몇 분 단위로 걸 수 있는지(R9 미확인 항목).
- 네이버 'AI 활용' 표시가 텍스트 블로그 글에도 적용되는지(R13 미확인). 표시 여부와 관계없이 본문의 "만든 방법" 줄은 유지한다.
- 상위 노출 글의 사진 수·길이 관행. 검색어 3개("LG전자 출장비", "로봇청소기 배터리 교체", "로봇청소기 고장")의 상위 글 5개씩을 사람이 열어 보고 `docs/research/R10` 끝에 기록한다.
