# 네이버 블로그 발행본 — 1주차 3편과 발행 절차

네이버 블로그에는 글쓰기 API가 없고, 이용약관(2026-10-01 시행)과 게시물 운영정책(2026-07-07 시행)이 **"네이버의 사전 허락 없이 자동화된 수단(예: 매크로 프로그램, 로봇(봇), 스파이더, 스크래퍼 등)을 이용하여 게재한 게시물"**을 제한한다(2026-11-18 원문 확인: policy.naver.com/policy/service.html, service_group.html). 그래서 이 폴더의 스크립트는 **붙여넣을 원고만 만든다.** 발행은 사람이 스마트에디터에서 하고, 예약발행 기능을 쓴다. 매크로·RPA·브라우저 자동화로 올리지 않는다.

## 글마다 하는 일

0. **수요자 문장 확인 (상시 규칙)**: 원고 `demand:`의 한 문장(누가·상황·판단할 것·검색어)을 소리 내어 읽고, 본문의 소제목들이 그 사람의 질문에 차례로 답하는지 확인한다. 새 글이면 `_TEMPLATE.md`를 복사해 이 문장부터 쓴다. 이어서 실제 검색어를 모으고 본문이 답하지 않는 검색어를 본다.
   ```bash
   node scripts/demand-research.mjs docs/blog/naver/01-battery-price.md
   ```
   `queries`를 시드로 구글 자동완성을 모아 `docs/research/data/suggest/<slug>.json`에 날짜와 함께 저장하고, "다루지 않는 검색어"(새 질문형 소제목 또는 별도 글 후보)와 태그 후보를 출력한다. 네이버 검색광고 API 키(`NAVER_SEARCHAD_API_KEY`·`NAVER_SEARCHAD_SECRET`·`NAVER_SEARCHAD_CUSTOMER_ID`)가 있으면 월간 검색량도 조회하고 `--write-scale`로 `scale:` 줄에 붙인다(실 API 미검증).

0-1. **사례 확보 [AI]** — 글마다 검증 가능한 사례 1건 이상을 `CASES.md` 순서(공적 사례 → 언론 보도 → 자사 제보 → 제조사 회신)로 찾아 출처 기록 `사례:` 줄로 넣는다. 직접 문의는 필수가 아니다.
1. **사람 몫 처리** — `[[판단: …]]`은 사람이 정하고, `[[현장: …]]`은 사람이 직접 한다(통화·촬영). 사람은 결과만 AI에게 넘긴다(통화 날짜와 답 요지, 사진 파일, 정한 바이라인 문장).
   [AI]는 받은 결과로 칸 자리의 본문을 격식체로 쓰고, front matter `firsthand:`(예: `firsthand: 2026-11-23 LG전자 고객센터 전화 문의(질문 4개)`)를 채운다. 답에 금액·기간이 있으면 출처 기록에 `직접:LG전자 고객센터 전화 2026-11-23` 줄을 추가한다. 바이라인은 정해진 문장을 모든 글에 넣는다.
2. **원문 재대조와 캡처 (전날)**
   ```bash
   node scripts/verify-sources.mjs docs/blog/naver/01-battery-price.md --evidence=docs/blog/evidence --write --suggest
   ```
   전역 Playwright를 스스로 찾으므로 `NODE_PATH`는 필요 없다. 자동으로 하는 일은 다음과 같다.
   - 일치한 출처 기록 행의 확인일과 `data_checked`를 오늘로 바꾼다(`--write`). 불일치 행과 이미지 행은 바꾸지 않는다.
   - 본문에는 있지만 출처 기록에 없는 숫자를 출처 페이지에서 찾아 `제안 - 값 | 주소 | 날짜 | (설명) | 원문 발췌` 행을 출력한다(`--suggest`). 그대로 붙이지 말고 설명 칸을 쓰고 발췌가 맞는지 본다.
   - 캡처마다 밝기·빨간 강조 테두리·해상도를 검사하고 실패하면 한 번 다시 찍는다. 그래도 실패하면 실패로 보고한다.
   - `docs/blog/evidence/<slug>/verify.json`에 실행 시각과 결과를 남긴다(`blog-status`가 읽는다).

   "불일치"가 나오면 [AI]가 원문을 열어 숫자·문구를 고친다. 본문, 출처 기록, (쓴다면) SNS 카드, 수정 이력을 함께 고친다. "이미지(캡처 판독 필요)" 행은 [AI]가 캡처 이미지를 읽어 숫자를 확인하고 그 행의 날짜를 바꾼다(`blog:status`가 판독 대기 행을 보여 준다). 본문 "만든 방법" 줄의 `마지막 대조일은 …`은 모든 행이 일치하면 `--write`가 갱신한다.
3. **점검** (여러 글을 함께 넣어야 글 사이 중복도 잡힌다)
   ```bash
   node scripts/check-claims.mjs docs/blog/naver/0*.md
   ```
   `WARN`(같은 어미 4연속 등)은 발행을 막지 않는다. 고칠지는 [AI]가 문맥을 보고 정해 처리한다. 경고까지 실패로 보려면 `--strict`를 붙인다.
3-1. **현황판**: 모든 글의 발행일·점검·사례·사람 몫·원문 대조·검색어 자료를 한 표로 본다.
   ```bash
   npm run blog:status
   ```
   `docs/blog/STATUS.md`를 다시 쓰고, 발행 2일 전까지 준비가 안 된 글이 있으면 종료 코드 1을 낸다(알림·CI 연결용).
4. **붙여넣기용 페이지 만들기**: 도메인이 확정돼야 한다.
   ```bash
   SITE_URL=https://실제도메인 node scripts/naver-export.mjs docs/blog/naver/01-battery-price.md
   ```
   `naver-out/<slug>.html`을 브라우저로 열면 제목·태그·본문·원문 캡처 PNG와 에디터 입력 순서가 나온다.
5. **스마트에디터**: 제목 → 본문 붙여넣기 → 인용구·표 모양 정리 → 캡처·사진 업로드(첫 장을 대표 이미지로) → 태그 → **모바일 미리보기** → 예약발행.
6. **발행 후**: 링크를 눌러 사이트가 열리는지, 관리자 KPI 패널의 "블로그·캠페인 유입"에 해당 캠페인이 잡히는지 본다. 댓글로 오류 지적이 오면 2번부터 다시 하고 수정 이력에 남긴다.

## 아직 확인하지 못한 것 (첫 글에서 확인)

- 붙여넣을 때 표·인용구·굵게가 유지되는지. 도구로 네이버에 접근할 수 없어 확인하지 못했다. 깨지면 에디터의 표·인용구 기능으로 다시 만든다.
- 예약발행을 며칠 뒤까지, 몇 분 단위로 걸 수 있는지(R9 미확인 항목).
- 네이버 'AI 활용' 표시가 텍스트 블로그 글에도 적용되는지(R13 미확인). 표시 여부와 관계없이 본문의 "만든 방법" 줄은 유지한다.
- 상위 노출 글의 사진 수·길이 관행. 검색어 3개("LG전자 출장비", "로봇청소기 배터리 교체", "로봇청소기 고장")의 상위 글 5개씩을 사람이 열어 보고 `docs/research/R10` 끝에 기록한다.
