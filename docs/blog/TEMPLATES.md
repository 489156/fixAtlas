# 수집형 블로그 글 템플릿 (4종) + 발행 전 점검표

> **네이버 발행본의 배치·문체·이미지·CTA·독자 신뢰 규칙은 `docs/blog/EDITORIAL_STANDARDS.md` §4~§9가 우선한다.** 아래 템플릿은 내용을 빠뜨리지 않기 위한 목록일 뿐, 이 순서와 소제목을 글마다 그대로 쓰지 않는다(템플릿 반복 금지). 완성 예시: `docs/blog/naver/01~03`.

모든 글의 목적은 하나다: **읽은 사람이 견적을 비교하거나 자기 사례를 제보하게 만드는 것.**
글은 넓게(유입), 데이터는 좁게(집중 셀) — 글 주제가 넓어도 제보 요청은 집중 셀로 모은다.

링크는 반드시 `node scripts/blog-link.mjs "<사이트 경로>" <글-slug> <위치>`로 만든다(UTM 없는 링크는 KPI에 집계되지 않음).
도메인이 확정되면 `SITE_URL=https://실도메인`으로 재생성한다.

## T1. 비용 리포트 (핵심 · 전체 글의 50% 이상)

- **제목 공식**: `[브랜드/모델·품목] [부품·작업] 비용 ([YYYY.MM] 공식가 기준[, 제보 N건])`
  예) 다이슨 V10 배터리 교체 비용 (2026.11 공식가 기준)
- **구성**
  1. **한 줄 결론** — 숫자 + 기준 + 표본. "공식몰 정상가 129,000원(2026-11-17 확인). 사용자 제보는 아직 3건이라 범위를 내지 않습니다."
  2. **공식·공개 가격 표** — 항목 | 가격 | 출처(링크) | 확인일 | 비고(정상가/회원가, VAT)
  3. **사용자 제보 요약** — n, 중앙값·중간 50%(n≥5일 때만), n<3이면 "범위 미표시"
  4. **견적서에서 확인할 것** — 부품비 / 기술료(수리비) / 출장비 분리 여부, 정품 여부, 보증
  5. **먼저 해볼 자가점검** — 안전등급 배지 + 3~5단계, 중단 기준
  6. **CTA 2개** — "내 견적 위치 확인하기"(제품 페이지) · "내 수리비 제보하기"(제보 폼, 제품·증상 프리필)
  7. **고지** — 정보 제공·안전 고지(아래 고정 문구), 제휴 링크가 있으면 제목·첫 문단에 표시
  8. **업데이트 이력** — 날짜 · 바뀐 숫자

## T2. 자가수리 가이드 (가구·가전 Safe Check 등급만)

- **제목 공식**: `[품목] [증상] 직접 고치기: 난이도 [n/5]·[시간]·부품비 [금액]`
- **맨 위 고정 박스**: 안전등급(Safe Check / Caution / Expert Only / Do Not DIY) + "이런 경우 직접 하지 마세요"
  - **Expert Only·Do Not DIY 항목은 절차를 쓰지 않는다.** 증상 설명 + 공식 AS 안내 + 비용 정보만.
- **구성**: 증상 확인 → 준비물(공구·부품, 공식 부품가와 출처) → 단계(사진은 직접 촬영본만) → 중단 기준 → 결과 확인 → **"해봤어요" 결과 제보 CTA(폼 B)**
- 금지: 배터리 분해, 전기부·가스·냉매·고전압 작업, 구조 하중을 받는 부위 임의 개조, 타 사이트 가이드·도면 복제(iFixit 등 라이선스).

## T3. 견적서 체크리스트 (구매·설치·수리 공통)

- **제목 공식**: `[작업] 견적서 보는 법: 항목별 정상 범위와 추가요금 체크리스트`
- **구성**: 견적서 항목 해설(표) → 공식 요금표가 있으면 원문 표(출처·확인일) → 흔한 추가요금과 미리 물을 질문 → 계약 전 확인(서면·VAT·추가요금 조건) → **"받은 견적 올리기" CTA(폼 C)**
- 업체 실명 비교·평가는 하지 않는다(명예훼손·임시조치 리스크). 항목과 금액 구조만 다룬다.

## T4. 월간 데이터 리포트 ("제보로 본 이달의 수리비")

- **구성**: 이달 신규 제보 수 → 새로 n≥5가 된 셀(모델×증상) → 셀별 중앙값 표(표본 수 병기) → **제보가 필요한 셀 목록**(다음 달 집중 요청) → 검색 결과 0건이었던 검색어 상위(=다음 글 주제) → 방법론(중앙값·사분위, 3/5/10건 기준, 반려·숨김 제외)
- 출처: 관리자 KPI 패널(`/admin`)의 0건 검색어·데이터 부족 제품·캠페인 표.

## 고정 문구 (모든 글 하단)

> 고장도감/FixAtlas의 정보는 사용자 제보와 공개자료를 기반으로 한 참고 정보입니다. 실제 수리비, 보증 적용 여부, 부품 수급, 안전성은 제품 상태, 지역, 수리업체, 제조사 정책에 따라 달라질 수 있습니다.
> 고전압, 배터리, 냉매, 가스, 방수 구조와 관련된 작업은 안전사고 위험이 있으므로 전문가 또는 공식 서비스센터를 이용하십시오.

제휴·보상이 있을 때만(제목 또는 첫 문단, 단정형): `이 글에는 제휴 링크가 있으며, 구매 시 고장도감이 수수료를 받습니다.`
(조건부 표현 "받을 수 있음"은 불명확 표시 예시로 지적됨 — 공정위 추천·보증 심사지침 2024-12-01, `docs/research/R5`)

## 발행 전 점검표 (모두 체크해야 발행)

- [ ] 모든 숫자에 출처 링크·확인일이 있다. 숫자를 원문 페이지에서 직접 다시 봤다.
- [ ] 정상가/회원가/할인가, VAT 포함 여부를 구분했다.
- [ ] 사용자 제보 수치는 표본 수와 함께 썼다. n<3 범위 미표시, n<5 중앙값 미표시 규칙을 지켰다.
- [ ] 안전등급을 표시했다. Expert Only·Do Not DIY는 절차를 쓰지 않았다.
- [ ] 다른 사이트의 글·사진·도면을 복제하지 않았다(링크·짧은 인용만).
- [ ] 업체·개인 실명 평가, 개인정보(영수증 이름·주소·전화)가 없다.
- [ ] 사이트 링크는 원고에 `site:/경로#배치`로 썼고, 붙여넣기 원고는 `naver-export`로 만들었다(UTM 자동).
- [ ] `node scripts/check-claims.mjs`와 `naver-export`가 경고 없이 통과했다(숫자 출처, 카드 숫자 대조, 어미 혼용, CTA 2개 이하, 이미지 3~6장, 표 3열 이하).
- [ ] 공개 문장(광고·제휴 여부, 언제 무엇을 확인했는지)과 `만든 방법:` 줄(AI가 한 일, `마지막 대조일`)을 넣었다.
- [ ] 편집자가 직접 한 일(문의·촬영·방문·실측)이 1건 이상 본문에 있고, front matter `firsthand:`에 날짜와 함께 적었다. 지어낸 경험·가상 인물은 없다.
- [ ] 발행 전날 `verify-sources --write`로 원문을 다시 대조했고, 이미지 속 수치는 AI가 캡처를 읽어 확인했다.
- [ ] 남은 사람 칸은 `[[판단]]`·`[[현장]]`뿐이고, 컴퓨터 작업이 사람 칸에 남아 있지 않다.
- [ ] FAQ 블록, "한 줄 결론" 같은 라벨, 다른 글과 같은 소제목·문장이 없다(`check-claims` 여러 글 동시 점검).
- [ ] **수요자 문장(`demand:`)을 맨 먼저 썼다**: 누가·어떤 상황에서·무엇을 판단하려고·어떤 검색어로 이 글을 읽는가. 발행 직전에 본문이 그 질문에 답하는지 다시 확인했다.
- [ ] front matter에 수요 기록(reader·need·urgency·scale·queries)을 썼고, 질의마다 답하는 소제목이나 문단이 있다.
- [ ] 제목이 질문+답 또는 서술 문장이고 품목(무선·로봇 등)이 분명하다. 후보 3~5개 중 독립 검토자 순위로 골랐다.
- [ ] 한 줄에 1~2문장이고 낯선 용어를 풀어 썼다. 본문 전체가 격식체이고 작업 보고 문장이 없다.
- [ ] 작성 다음 날(24시간 뒤) 원문을 다시 열어 숫자를 대조한 뒤 예약발행했다. 자동화 도구로 올리지 않았다.
- [ ] 모바일 미리보기에서 표·인용구·카드가 깨지지 않는다.
- [ ] 제휴·보상이 있으면 단정형 표시를 제목·첫 문단에 넣었다.
- [ ] 고정 문구를 넣었다.
